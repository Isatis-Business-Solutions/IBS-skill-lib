# Production record

Every video project keeps its whole production in one folder, so any agent (this skill, a later storyboard or
video-generation skill, or a person) can pick it up, change one shot and render again without redoing the rest.

```text
<project>/
  production.json   the record: brief, skeleton, every shot with its prompt, takes and choice (source of truth)
  LOG.md            what changed, when and why (append only, newest at the bottom)
  shotlist.md       the readable version for the user (optional; production.json wins when they differ)
  timeline.json     the edit
  gen/              generated or delivered footage and images, named by shot id: S03.mp4, S03-b.mp4, R1.png
  .placeholders/    placeholder clips for shots that do not exist yet (not committed)
```

## Rules

- **Read `production.json` first** when it exists, and the last entries of `LOG.md`. Change only what the
  request is about: one shot, one caption, one transition.
- **Update both after every change**: the record (status, chosen take, notes) and one line in `LOG.md`
  (date, what, why). A render gets an entry in `renders`.
- **Shot ids are stable.** Never renumber; a new shot gets the next free id, a dropped shot gets
  `status: "dropped"`.
- **A take is never deleted from the record.** A rejected take keeps its `verdict` and what went wrong; that is
  what the next prompt is improved from.

## production.json

```json
{
  "project": "name", "schema": 1, "updated": "YYYY-MM-DD",
  "brief": { "goal": "After this clip [who] must [think, feel or do] …", "audience": "", "channel": [], "format": "9:16", "length_s": 45 },
  "skeleton": { "shape": "…", "beats": [ { "n": 1, "name": "Cold open", "role": "tension", "thinks": "…" } ] },
  "styles": { "STYLE_V1": "style, audio and avoid block appended to every video prompt" },
  "refs": [ { "id": "R1", "kind": "image", "title": "", "prompt": "", "file": "gen/R1.png", "status": "todo", "takes": [], "chosen": null } ],
  "shots": [ {
    "id": "S03", "beat": 2, "title": "", "source": "gen | combo | code | real",
    "size": "ms", "move": "hand", "gen_seconds": 8, "aspect": "9:16",
    "prompt": "", "style": "STYLE_V1", "frames": { "first": "R1", "last": "…" },
    "graphic": { "type": "mail" },
    "file": "gen/S03.mp4", "use": "2,4 s",
    "status": "todo | placeholder | generated | chosen | redo | built | dropped",
    "takes": [ { "file": "gen/S03-a.mp4", "tool": "Veo 3.1", "date": "", "verdict": "ok | redo", "note": "" } ],
    "chosen": "gen/S03-a.mp4", "notes": []
  } ],
  "open": [], "renders": [ { "file": "", "date": "", "kind": "animatic | draft | final", "note": "" } ]
}
```

- `source`: `gen` generated by a video model, `combo` generated with a code layer on top (callout, card),
  `code` a graphic shot from this skill, `real` filmed footage.
- When a take is chosen, copy or rename it to the shot's `file` (the path the timeline uses), so the timeline
  never changes because of a new take.

## Animatic

Before the footage exists, render the edit with placeholders: `scripts/placeholders.mjs production.json` makes a
labelled clip for every shot whose `file` is missing, and the timeline points at it with `fallback`. As takes
arrive, the animatic turns into the edit without touching the timeline.
